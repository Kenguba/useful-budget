# use — 仓库规范

ken 的个人站点仓库：收集便宜、有用的技能与资源。GitHub Pages 发布，入口为根目录导航页。

- 仓库：https://github.com/Kenguba/useful-budget
- 网站：https://kenguba.github.io/useful-budget/

## 目录规范

根目录只保留三样东西，其余一律进项目目录：

| 路径 | 用途 |
| --- | --- |
| `.github/workflows/` | 自动化（定时刷新 + 发布 Pages），必须在根目录，GitHub 的硬性要求 |
| `index.html` | 全站入口导航页，只放项目卡片链接，不放具体业务内容 |
| `README.md` | 本规范文件 |

每个项目 = 一级目录一个，自带全套文件（页面、数据、脚本、图标等），互不引用、互不依赖：

```
frontend/<project>/           # 例：frontend/skill-board/
  index.html         # 项目页面（通过 /useful-budget/frontend/<project>/ 访问）
  data/              # 项目数据（如有）
  scripts/           # 项目脚本（如有）
  icons/             # 项目图标 / PWA 资源（如有）
```

## 新增项目规范

1. 目录名：全小写英文 + 连字符（如 `ai-links`），不使用中文、空格、下划线。
2. 在根 `index.html` 导航页加一张卡片：项目名、一句话说明、状态标签，链接指向 `frontend/<project>/`（相对路径）。
3. 项目需要定时更新的，在 `.github/workflows/` 里处理：脚本路径写全（含项目目录前缀，如 `frontend/skill-board/scripts/refresh.py`），数据提交范围写明项目目录（如 `git add frontend/skill-board/data/`）。
4. 发布方式全局统一：workflow 用 `actions/upload-pages-artifact` 上传仓库根目录（`path: .`），根导航与所有项目一次发布，不给单个项目单独建发布流程。
5. 项目下线：删其目录 + 删导航页对应卡片，两处缺一不可。

## 子域名（Cloudflare 转发）

**主域名（`xxxxx.asia`，无前缀）= 全站总体预览页**：打开主域名就是根目录导航页 `index.html`（「便宜、有用的，都在这」），与 `kenguba.github.io/useful-budget/` 内容一致，不给任何单个项目占用。主域名不走通配，须单独配 DNS 与路由（见 `backend/README.md` 迁移清单）。

各项目各有一个子域名入口，经 Cloudflare Worker 转发到本仓库对应的 Pages 目录，与 `kenguba.github.io/useful-budget/frontend/<project>/` 内容一致：

| 项目 | 子域名 |
| --- | --- |
| （全站入口）`index.html` | `xxxxx.asia`（主域名） |
| `frontend/skill-board/` | `skill.xxxxx.asia` |
| `frontend/ai-shop/` | `ai.xxxxx.asia` |
| `frontend/cloud-phone/` | `phone.xxxxx.asia` |
| `frontend/cloud-pan/` | `pan.xxxxx.asia` |
| `frontend/ip-check/` | `ip.xxxxx.asia` |
| `frontend/2fa-auth/` | `2fa.xxxxx.asia` |
| `frontend/wechat-bridge/` | `wechat.xxxxx.asia`（仅子域名，不进总汇） |

**首页（总汇）收录规则（2026-11-07 ken 定）**：进总汇首页的只有 7 个——ai、skill、phone、pan、ip、2fa、ui。wechat 只开子域名 `wechat.xxxxx.asia`，不进总汇：不加短路径、不上首页卡片。以后新增项目先定类别：进首页的，子域名、总汇短路径、首页卡片三样一起加；不进首页的，只加子域名，并在子域名清单里登记注明，免得误加。

完整域名不写入本仓库（公开仓库，避免暴露站长域名）；解析与 Worker 配置在站长的 Cloudflare 账号里维护。全部后端 Worker 的源码留档统一放在仓库根目录的 `backend/` 里（说明见 `backend/README.md`）（`backend-proxy.js.back`、`site-router.js.back`、`jpcard.js.back`），迁移时直接取用，配套的通配 DNS/路由配置清单写在 site-router 留档的文件头。

## 约定

- 链接与仓库名绑定：Pages 地址为 `kenguba.github.io/useful-budget/frontend/<project>/`，项目目录名即网址路径段，改目录名 = 改网址，慎重。
- **xxxx 占位命名**：文件名与文档中连续 3 个以上 x（`xxxx`）表示占位，代替真实或未定的部分；需要占位的文件直接以占位名命名，如 `xxxxx.md`。
- 数据文件与代码分开提交：自动刷新只提交 `data/` 变更，提交信息形如 `data: refresh YYYY-MM-DD`。
- 脚本一致性：仓库内脚本必须与线上实际运行的版本保持一致。项目脚本（如各项目 `scripts/refresh.py`）以仓库 main 为准，本地镜像/工作副本改完必须推送，禁止只改本地；后端 Worker 以 Cloudflare 已部署版为准，先部署、再把源码同步回 `backend/` 留档。发现不一致时以线上为准，并立即对齐。
- 本规范有变更时，先改本文件，再改实际结构，保持两者一致。

## 页面规范

- **加载顺序（2026-11-07 定，全站适用）**：所有页面（含总汇 SPA 与各单站）一律按六级顺序加载——（1）UI 先出：先显示全部 HTML 与 CSS，与 UI 有关的 JS 同步先加载、先就绪，界面先成形先能点；数据未到处用骨架加流光按真实版式占位，数据到后原地替换，不得让数据或重活拖住 UI 出场。（2）核心数据紧接着：当前页第一屏要用的数据紧随 UI 之后拉取填充。（3）轻模块预加载：当前页可交互后，空闲时按顺序在后台预加载轻量模块（约 150 KB 内、只拉代码不拉易变数据）；层叠焦点卡视为强意图，该模块立即预加载。（4）长列表懒加载：长列表与图片快进视口才加载，分批规则见「列表触底加载」条。（5）重功能按需：重、低频、特定动作才用的功能（如店铺目录、价格变动表、历史日期榜），用户点了才拉，没点永不拉。（6）不重要的延迟：不影响当前使用的，推迟到浏览器空闲或首屏忙完后。判断口径：贵不贵、会不会去、会不会过期，三关都过才配预加载；实时数据（如 IP 检测结果、盘搜搜索结果）永不预取；预加载永远给用户当前操作让路，用户点未加载模块时该模块插队到最前；已加载模块不卸载，返回直接用原视图，再进只按数据版本补拉数据、代码不重拉。
- **列表触底加载（2026-11-03 定，全站适用）**：凡是分页 / 分批展示的列表，一律做成滚动触底自动加载下一批，不做「加载更多」按钮、不做「上一页 / 下一页」分页。实现借鉴 `frontend/ai-shop/` 店铺目录的哨兵模式：`IntersectionObserver` 哨兵元素 + `rootMargin` 提前约 300px 触发 + 在途锁防重复触发 + 加载中转圈提示；全部加载完显示「已展示全部 N 条」；拉取失败不得空转自动重试，给一次点击重试即可。参考实现：`frontend/ai-shop/index.html`（店铺目录哨兵）、`frontend/cloud-pan/assets/app.js`（每日更新页）。
- **移动端适配（2026-11-03 定）**：所有页面必须在手机宽度（≤860px）下正常可用——顶栏 / 工具栏等固定区域不得横向溢出撑宽页面（放不下就换行或横滚），内容区满宽显示；新页面或改版上线前须按手机宽度核对一遍再发布。每个界面都要单独考虑手机端，不是一处改完就算完。cloud-pan 的具体口径：左右间距收紧（外层 8px、卡片内 12px）；顶栏「求片」按钮手机端隐藏；「保持联系」浮钮手机端缩小并贴右边吸附。
- **筛选条（2026-11-03 定）**：筛选条放搜索框上方；单行横滚，不换行、不显示滚动条。
- **行末无句号（2026-11-03 定，全站适用）**：页面可见文案每行末尾默认不加句号（。）；一行内有多句时用分号分隔。
- **侧边浮钮低层级（2026-11-03 定，cloud-pan「保持联系」）**：辅助入口不抢主内容层级——白底（半透）灰字、细边框、弱阴影的贴边竖排标签，禁止饱和色块底 + 白色粗体 + 彩色光晕阴影；全站统一默认位置（贴右边缘无间隔，距底桌面 40px / 手机 36px），位置固定不可拖拽，避免各页位置漂移、滑动时被误拖走。
- **点击高亮跟随形状（2026-11-04 定，全站适用）**：可点击元素的点按高亮须与元素自身形状一致；圆形、胶囊形等非矩形元素不得出现矩形高亮，仅矩形元素本身可用矩形高亮。
- **动效自然度（2026-11-07 定，全站适用；源自抖音 @费纸张《四个技巧让 AI 做的动效更自然》）**：（1）随时打断——可被操作打断的动效用 `transition` 实现，不用 `@keyframes`；动效进行中再次操作须从当前状态就地转向新目标，不得从头重播或等播完才响应。（2）轻轻退场——退场元素只移出一小段（约 20–50px）即同步淡出并加轻微模糊（位移、`opacity`、`blur` 一起收尾），不得一路飞出屏幕。（3）柔和切换——内容 / 图标切换用交叉淡化，叠加轻微缩放与模糊，不得瞬时显隐硬切。（4）入场缓出——入场动画用强缓出曲线 `cubic-bezier(.16, 1, .3, 1)`，不用匀速 / 线性；验收须用回放加慢动作逐帧自查并与速度 / 位置曲线对比，只凭正常速度肉眼看一遍不算验收。
- **跨子域名共享偏好 Cookie `A`（2026-11-04 定，全站适用）**：主题 / 语言 / 日夜偏好用 Cookie `A` 在 jpedu.asia 各子域名间共享，不走后端存储；Cookie 属性为 `Domain=jpedu.asia; Path=/; Max-Age=31536000`（一年）`; SameSite=Lax`，https 下加 `Secure`，由前端 JS 读写（代价：每次发往 `*.jpedu.asia` 的请求都会自动带上这几个字节）
  - 格式：`A=` 后接三段数字：第 1 位语言（0 中文、1 英语，后续可扩展）、第 2 位日夜（0 黑色、1 浅色）、其余为主题号 1–12 不补零，如 `A=0112` 表示中文、浅色、第 12 套，`A=009` 表示中文、黑色、第 9 套
  - 通用规则：打开页面时先读 `A`、再读本站 localStorage，`A` 优先；改主题 / 日夜 / 语言时双写 `A` 与本站 localStorage；写 `A` 时须保留自己不管理的段位（如 ai-shop 无语言切换，写 `A` 时原样保留语言位）；`A` 不存在但本站有 localStorage 时，首次打开把本站现值写入 `A` 作为种子；`A` 与本站记录都不存在时用本站默认值
  - ai-shop 是单槽（2026-11-04 晚改定，全站一套主题）：localStorage `aishop.theme.v1` 存 `{t, d}`，t 为全站唯一主题位（0–11 对应 1–12 套）、d 为日夜；报价单与店铺目录两个页签共用同一套主题，切页签不换色、也不写 `A`；读 `A` 时主题号直接就是全站主题；只有在主题面板里真正点选 / 滑选了颜色、或单击主题钮切换日夜时才写 `A`；旧版双槽存量 `{q, s, d}` 首次打开时按 q（原报价单槽）迁移为 t，`A` 存在时以 `A` 为准
  - ip-check 与 2fa-auth 是单槽：主题只有一个槽，读 `A` 后主题号 1–12 直接作为本站主题，语言、日夜也全部跟 `A` 走；ip-check 的 localStorage 键为 `ip-theme-idx` / `ip-dark` / `ip-lang`，与 `A` 双写
  - cloud-phone 是单槽（2026-11-06 接入）：localStorage 键为 `phone-theme-idx` / `phone-dark` / `phone-lang`，与 `A` 双写；读 `A` 后主题号 1–12 直接作为本站主题，语言、日夜也全部跟 `A` 走；切页签不写 `A`，只有在主题面板真正点选 / 滑选、点刷新主题、单击主题钮切换日夜或切换语言时才写 `A`；接入前本站无 localStorage 存量、无种子可迁，`A` 与本站记录都不存在时用本站默认值（第 12 套、中文、浅色）
  - cloud-pan 是单槽（2026-11-06 接入）：localStorage 键为 `pan-theme-idx` / `pan-dark` / `pan-lang`，与 `A` 双写；读 `A` 后主题号 1–12 直接作为本站主题，语言、日夜也全部跟 `A` 走；主题色值与 ai-shop 线上 12 套逐值一致、另加第三光斑 orb3；只有在主题面板真正点选 / 滑选、单击主题钮切换日夜或切换语言时才写 `A`；接入前本站无 localStorage 存量、无种子可迁，`A` 与本站记录都不存在时用本站默认值（第 12 套、中文、浅色）；顶栏不放安装钮（安装入口收进 APP 页）、胶囊按 34px 规格、右侧控件组 flex:none、主题钮固定尺寸、品牌名可省略，保证主题钮在窄屏与系统大字体下不被挤出屏
- **栅格参考（格斯特纳 58 单位复合网格，非强制规范）**：总宽 58 个单位，预留栏间距后可整除切分 1–6 栏——1 栏 58、2 栏 28、3 栏 18、4 栏 13、5 栏 10、6 栏 8，每栏宽度均为整数、不出半格；此为印刷/版式排版参考，网页端仍用 12 / 8 / 4 栏响应式栅格，不以 58 单位替代
