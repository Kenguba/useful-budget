# frontend — 前端与 UI 规范

本目录下各项目的页面与 UI 通用规范，做页面时读这一份。各站自己的实现细则在各站 README 里。

配套审计参考：[AI味审计清单.md](AI味审计清单.md)——征兆与改法对照，逐项排查页面时按需读，不替代本文件正文，冲突以正文为准。

## 页面规范

- **等宽数字（全站适用）**：界面中展示数值的数字统一使用等宽数字（OpenType `tnum`），尤其是金额、价格、数量、计数、时间、日期、百分比、排行及动态更新值；H5 在现有全局/组件字体规则中使用 `font-variant-numeric: tabular-nums;`，避免数字变化时宽度跳动、表格列不齐。不得为此把整段文字改成等宽字体，不叠加重复 CSS 覆盖；字体需支持 `tnum`，上线前核对移动端、桌面端和动态数字的实际显示。
- **加载顺序（2026-11-07 定，全站适用）**：所有页面（含总汇 SPA 与各单站）一律按六级顺序加载——（1）UI 先出：先显示全部 HTML 与 CSS，与 UI 有关的 JS 同步先加载、先就绪，界面先成形先能点；数据未到处用骨架加流光按真实版式占位，数据到后原地替换，不得让数据或重活拖住 UI 出场。（2）核心数据紧接着：当前页第一屏要用的数据紧随 UI 之后拉取填充。（3）轻模块预加载：当前页可交互后，空闲时按顺序在后台预加载轻量模块（约 150 KB 内、只拉代码不拉易变数据）；层叠焦点卡视为强意图，该模块立即预加载。（4）长列表懒加载：长列表与图片快进视口才加载，分批规则见「列表触底加载」条。（5）重功能按需：重、低频、特定动作才用的功能（如店铺目录、价格变动表、历史日期榜），用户点了才拉，没点永不拉。（6）不重要的延迟：不影响当前使用的，推迟到浏览器空闲或首屏忙完后。判断口径：贵不贵、会不会去、会不会过期，三关都过才配预加载；实时数据（如 IP 检测结果、盘搜搜索结果）永不预取；预加载永远给用户当前操作让路，用户点未加载模块时该模块插队到最前；已加载模块不卸载，返回直接用原视图，再进只按数据版本补拉数据、代码不重拉。
- **SPA 单页面（全站适用）**：页面做成单页面，站内切换不整页重载；返回时恢复原视图与滚动位置
- **交互不重绘（全站适用）**：点按、输入等高频交互只就地局部更新、反馈先行，不整表重绘或重排；确需全量对账时放到下一帧再做
- **列表触底加载（2026-11-03 定，全站适用）**：凡是分页 / 分批展示的列表，一律做成滚动触底自动加载下一批，不做「加载更多」按钮、不做「上一页 / 下一页」分页。实现借鉴 `frontend/ai-shop/` 店铺目录的哨兵模式：`IntersectionObserver` 哨兵元素 + `rootMargin` 提前约 300px 触发 + 在途锁防重复触发 + 加载中转圈提示；全部加载完显示「已展示全部 N 条」；拉取失败不得空转自动重试，给一次点击重试即可。参考实现：`frontend/ai-shop/index.html`（店铺目录哨兵）、`frontend/cloud-pan/assets/app.js`（每日更新页）。
- **移动端适配（2026-11-03 定）**：所有页面必须在手机宽度（≤860px）下正常可用——顶栏 / 工具栏等固定区域不得横向溢出撑宽页面（放不下就换行或横滚），内容区满宽显示；新页面或改版上线前须按手机宽度核对一遍再发布。每个界面都要单独考虑手机端，不是一处改完就算完。cloud-pan 的专属口径（间距、求片钮、联系浮钮）见 [cloud-pan/README.md](cloud-pan/README.md)
- **筛选条（2026-11-03 定）**：筛选条放搜索框上方；单行横滚，不换行、不显示滚动条。
- **行末无句号（2026-11-03 定，全站适用）**：页面可见文案每行末尾默认不加句号（。）；一行内有多句时用分号分隔。
- **侧边浮钮低层级（2026-11-03 定，cloud-pan「保持联系」）**：辅助入口不抢主内容层级——白底（半透）灰字、细边框、弱阴影的贴边竖排标签，禁止饱和色块底 + 白色粗体 + 彩色光晕阴影；全站统一默认位置（贴右边缘无间隔，距底桌面 40px / 手机 36px）；可拖拽并记住位置，默认位置只对没有拖动过的生效。
- **点击高亮跟随形状（2026-11-04 定，全站适用）**：可点击元素的点按高亮须与元素自身形状一致；圆形、胶囊形等非矩形元素不得出现矩形高亮，仅矩形元素本身可用矩形高亮。
- **点击热区与安全三角（2026-11-10 定，全站适用）**：能点的范围须比看到的大一圈——可点元素的热区大于其可见区域，点在整块热区内即执行，不只点中图标或文字才算；相邻热区紧挨着、不留缝隙，列表行热区向外扩并填满行间空隙，点在两行中间不落空；有子菜单的须加安全三角——从父项到子菜单连成的三角形区域内，指针斜向移向子菜单时同级项暂不响应、子菜单保持打开，移出三角形才切换
- **动效自然度（2026-11-07 定，全站适用；源自抖音 @费纸张《四个技巧让 AI 做的动效更自然》）**：（1）随时打断——可被操作打断的动效用 `transition` 实现，不用 `@keyframes`；动效进行中再次操作须从当前状态就地转向新目标，不得从头重播或等播完才响应。（2）轻轻退场——退场元素只移出一小段（约 20–50px）即同步淡出并加轻微模糊（位移、`opacity`、`blur` 一起收尾），不得一路飞出屏幕。（3）柔和切换——内容 / 图标切换用交叉淡化，叠加轻微缩放与模糊，不得瞬时显隐硬切。（4）入场缓出——入场动画用强缓出曲线 `cubic-bezier(.16, 1, .3, 1)`，不用匀速 / 线性；验收须用回放加慢动作逐帧自查并与速度 / 位置曲线对比，只凭正常速度肉眼看一遍不算验收。（5）无意义循环禁——呼吸发光、pulse / ping、视差漂浮不用，非实时状态一律静态。（6）不用 `transition-all`，须点名过渡属性；悬停只变颜色或表面、不放大，按压才微缩。（7）只动画 `transform` 与 `opacity`，不动画宽高、`top` / `left` 与大面积模糊（弱设备卡顿源）。
- **图标不用 emoji（全站适用）**：标题、按钮、卡片的图标一律用内联 SVG 或 ico，不拿 emoji 充图标；全站同一套线条图标、同一尺寸与描边，图标颜色随所在文字层级、不自带彩色；无信息增量的图标直接去掉
- **主题选中高亮（全站适用）**：可选项未选时预置 1.5px 透明边框占位；选中时边框变当前主题强调色、底填当前主题浅色、整块放大 1.04 并带光晕阴影；悬停与滑选同款
- **深色不借浅底（全站适用）**：深色模式下元素不得借用浅色背景变成实心白块
- **间距刻度（2026-11-10 定，全站适用）**：间距、内边距、行高一律取 4px 刻度（2px 仅小控件内微调），不用 13px、11px 等任意值；同类元素同尺寸同间距，组内间距小于组间间距；图标、标签、数字各成一列对齐
- **文字与边框（2026-11-10 定，全站适用）**：文字只分主、次、弱三级且同出一套中性色阶，不堆近似色；边框用主文字色 6–10% 的发丝线，不用彩色粗边；强调色每屏只点主操作、选中与关键数字，语义色只表意；带色文字与背景对比度不低于 4.5:1；数字格式全屏统一（千分位、小数位一致）；渐变只许整片平滑的表面渐变（如头部主题色弥散），不用色块光斑、彩色发光与渐变文字；主题选中高亮的光晕阴影是小面积强调时刻、为例外
- **字形（2026-11-10 定，全站适用）**：标题字重 400–500，600 仅罕用强调，不用 800/900；层级靠字号与颜色拉开，不靠加粗堆叠；英文标签用句首大写、不用全大写加宽字距；小字不用负字距；强调不用斜体、改颜色或字重
- **文案克制（2026-11-10 定，全站适用）**：界面文案不用感叹号、不用问候式标题、不用浮夸词，标题直接说清这页是什么、为谁做；搜索等占位符写短；涨跌与变化数字须带参照（如「较上月」）；无来源的规模、排名类宣称不写；示例与演示数据用可信数字，不用 123,456 与占位符
- **圆角与徽章（2026-11-10 定，全站适用）**：圆角按尺寸分档——控件 8–10、卡片 12–16、面板 14–20，嵌套圆角等于外圆角减间距且不小于 4，不全做胶囊；计数、状态、快捷键改安静的等宽纯文字，不用发光胶囊；徽章每屏至多一个且为安静文字款
- **图表与数据卡（2026-11-10 定，全站适用）**：一屏一主图且主图最大，辅图须异类更小；一图只用一个强调色点关键项、其余中性阶，网格与标签弱化，不用彩虹柱与发光柱；数据卡只放数字、标签与带参照的变化，不塞迷你图与装饰图标；等宽等样卡片不连排成片，须有大小节奏
- **视觉素材（2026-11-10 定，全站适用）**：配图优先展示真实产品、真实数据或其实际产出，不用光泽 3D 色块、星云、发光大脑等装饰填充；图内不烘焙文字、按钮与假标志，文字一律页面实字；图片边缘须与页面背景融合（同底色或渐隐处理），不留生硬矩形边；配图只放在真正有帮助处
- **方向与模板检验（2026-11-10 定，新站与改版适用）**：动手前先定方向四行——产品性格（用具体词，不用干净、现代等万能词）、所属世界、1–2 个允许浓墨重彩的内容时刻、一个只属于该产品的签名细节；界面外框（导航、按钮、文字）保持安静，浓墨只给那 1–2 个时刻；验收加一条：把产品名换成别家这屏还成立，就是方向没定好
- **跨子域名共享偏好 Cookie `A`（2026-11-04 定，全站适用）**：主题 / 语言 / 日夜偏好用 Cookie `A` 在 jpedu.asia 各子域名间共享，不走后端存储；Cookie 属性为 `Domain=jpedu.asia; Path=/; Max-Age=31536000`（一年）`; SameSite=Lax`，https 下加 `Secure`，由前端 JS 读写（代价：每次发往 `*.jpedu.asia` 的请求都会自动带上这几个字节）
  - 格式：`A=` 后接三段数字：第 1 位语言（0 中文、1 英语，后续可扩展）、第 2 位日夜（0 黑色、1 浅色）、其余为主题号 1–12 不补零，如 `A=0112` 表示中文、浅色、第 12 套，`A=009` 表示中文、黑色、第 9 套
  - 通用规则：打开页面时先读 `A`、再读本站 localStorage，`A` 优先；改主题 / 日夜 / 语言时双写 `A` 与本站 localStorage；写 `A` 时须保留自己不管理的段位（如 ai-shop 无语言切换，写 `A` 时原样保留语言位）；`A` 不存在但本站有 localStorage 时，首次打开把本站现值写入 `A` 作为种子；`A` 与本站记录都不存在时用本站默认值
  - 各站实现细则（单槽存法、双写时机、localStorage 键）按需看各站 README：[ai-shop](ai-shop/README.md)、[ip-check](ip-check/README.md)、[2fa-auth](2fa-auth/README.md)、[cloud-phone](cloud-phone/README.md)、[cloud-pan](cloud-pan/README.md)
- **栅格参考（格斯特纳 58 单位复合网格，非强制规范）**：总宽 58 个单位，预留栏间距后可整除切分 1–6 栏——1 栏 58、2 栏 28、3 栏 18、4 栏 13、5 栏 10、6 栏 8，每栏宽度均为整数、不出半格；此为印刷/版式排版参考，网页端仍用 12 / 8 / 4 栏响应式栅格，不以 58 单位替代
- **栅格应用口径**：小项目只借用 58 复合网格的思想——先预留栏间距、再切分栏数、保证每栏宽度为整数，不直接套用 58 这个数字；与现有布局发生冲突时，先按「冲突选择」说明冲突、请 ken 决定，不擅自改动
