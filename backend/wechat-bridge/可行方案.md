# 把常驻 AI 助手桥接到微信聊天：2025–2026 可行路线研究

调研日期：2026-11-07。使用者画像：**中国大陆个人用户、无企业营业执照**，要在微信里像和好友聊天一样给自己的 AI 助手发文字/图片，助手 **约 1 分钟内回复**，且能**主动推送提醒**。助手侧已有云服务器、Cloudflare 账号、Webhook/轮询能力。

**标记约定**：【官方】= 微信/企业微信/腾讯官方文档或官方仓库原文；【项目】= 开源项目官方文档；【社区】= 论坛/GitHub Issue/博客实测，仅作经验参考。所有链接均为实际打开/检索到的页面。

---

## Summary（先给结论）

2026 年的格局和 2024 年完全不同，排序如下：

1. **首选（聊天体验最像「和好友聊天」、零封号）：微信官方 ClawBot 通道（iLink / `openclaw-weixin`）** — 2026-03-22 前后腾讯官方推出的个人微信 Bot 插件，扫码登录、长轮询收消息、无需公网回调，CowAgent / AstrBot / LangBot 均已接入。文本/图片/语音/文件/视频私聊都支持。**唯一硬伤：主动推送受限**——回复必须带入站消息的 `context_token`，社区实测约 **24 小时窗口 + 每下发约 10 条需用户再互动一次**，做不了「三天后冷启动提醒」。
2. **首选之二（主动推送最可靠、官方 API、个人可注册）：企业微信自建应用 + 微信插件** — 个人可注册未认证企业微信并建自建应用（多方实测跑通），回调收消息 + `message/send` **无时间窗口地主动发消息**（仅频控），异步 AI 回复天然成立。代价：会话长得像「企业应用」而非好友；需要一台**固定公网 IP** 的服务器做回调和 API 调用（企业可信 IP 白名单），**纯 Cloudflare Worker 做发送端不成立**（见第 6 节）。
3. **推荐组合**：ClawBot 负责日常聊天 + 企业微信应用消息负责定时/冷启动提醒，两条都是官方通道、互不干扰。
4. **微信客服（kf）**：用户侧体验是微信内最像原生聊天的客服会话，但发送被锁死在 **用户发消息后 48 小时内、最多 5 条**【官方】，官方条款明说 48 小时后不能主动发——**不满足长期主动提醒**，且 CowAgent 的 kf 通道把「已认证企业微信」列为前提（与 kf 条款「未验证可开通但限人数」有出入，见 3 节）。
5. **个人订阅号**：能开服务器配置、能被动回复，但**个人未认证号用不了客服消息接口**【官方明文：仅企业主体已认证】，所以 AI 超过 5 秒就只能「先回一句正在思考，用户再发任意消息来取答案」——**不满足 1 分钟内自动回复**，更不能主动推送。2024-10 开放的「个人服务号」也救不了：个人不能做微信认证，接口权限与个人订阅号基本相同【社区/二手来源，官方文档未单列】。
6. **个人号逆向框架（Hook/iPad 协议/Web 协议）：2025–2026 集体退场或高风险** — Gewechat 已停维并自称「技术归档」、WeChatFerry 已归档停维且旧版微信被强制升级挡住、itchat/Web 协议对绝大多数账号已不可登录、wxauto 原版因微信 4.0 渲染架构变更停维。还活着的只有付费 iPad 协议（PadLocal 约 200 元/月、Gewe 付费版），封号是社区常态反馈。**不要用主力微信号尝试。**

## Findings

### 1. 微信公众号路线

**个人订阅号能不能开「服务器配置」？能。【官方+项目】**
- 官方《消息与事件推送介绍》给出通用配置流程：填 URL、Token、EncodingAESKey，微信发 GET 带 `signature/timestamp/nonce/echostr`，校验 `sha1(sort(token,timestamp,nonce))` 后原样返回 `echostr` 即接入生效；**URL 必须以 http:// 或 https:// 开头，分别只支持 80 / 443 端口；消息体仅支持 XML**。文档未按账号类型限制此能力。来源：https://developers.weixin.qq.com/doc/subscription/guide/dev/push/
- CowAgent 文档直接以个人订阅号为一等公民给出「设置与开发 → 基本配置 → 服务器配置」接入步骤，证明个人号可跑通。来源：https://docs.cowagent.ai/zh/channels/wechatmp

**被动回复 5 秒限制细节。【官方】**
- 用户消息以 POST 推到开发者 URL，开发者在**响应包里返回 XML** 即为被动回复（支持文本/图片/语音/视频/音乐/图文；图片等需先用素材接口上传拿 MediaId）。
- **微信服务器 5 秒内收不到响应就断开并重试，总共重试 3 次**；需用 MsgId（事件用 FromUserName+CreateTime）排重。
- 无法 5 秒内处理完时，官方要求**直接回复 `success` 或空串**，微信不再重试、也不报错，后续「可以使用客服消息接口进行异步回复」；若什么都不回或回了 JSON 等异常数据，用户端会看到「该公众号暂时无法提供服务，请稍后再试」。
- 来源：https://developers.weixin.qq.com/doc/subscription/guide/product/message/Passive_user_reply_message.html
- 注：CowAgent/LangBot 文档里出现的「15 秒内回复」是把 3 次重试累计成的经验窗口，不是官方单次时限承诺；依赖重试窗口攒 AI 回复并不可靠，主流框架对个人订阅号实际采用的是**「先回『正在思考中』，生成完后等用户再发任意一条消息，再把答案作为被动回复带出」**（CowAgent 公众号页明文描述此交互）。这意味着：**慢回复不会自动到达，必须用户再戳一下。**

**客服消息接口：个人未认证订阅号不能用，这是本路线的死穴。【官方】**
- 接口 `POST https://api.weixin.qq.com/cgi-bin/message/custom/send`，规则：用户发消息后 **48 小时内、最多下发 5 条**；点菜单/关注/扫码则只有 3 条、1 分钟。
- 同页「适用范围」表写死：公众号、服务号均为**「仅认证」**，并定义为「**仅允许企业主体已认证账号调用，未认证或不支持认证的账号无法调用**」。个人主体无法完成企业主体微信认证，因此个人订阅号/个人服务号都拿不到这个接口，也就**没有任何异步/主动下发通道**。
- 来源：https://developers.weixin.qq.com/doc/subscription/api/customer/message/api_sendcustommessage

**服务号注册门槛。**
- 传统口径：服务号仅对企业、政府、媒体、事业单位等组织开放，个人只能注册订阅号；企业认证 300 元/年。【二手来源多方一致】例：https://yiban.io/geo/31847
- **2024 年 10 月起的变化**：微信开放「个人服务号」，经「服务号助手」小程序可用个人身份注册，无强制实名（粉丝达 1 万、开通带货/付费等才需实名）。但**个人服务号无法做微信认证，高级接口（客服消息、模板消息、网页授权、支付）仍无权限，接口能力与个人订阅号基本相同**。【社区/二手来源，未找到官方文档单列此口径，下单决策前建议在公众平台后台实测接口权限页】来源：https://yiban.io/blog/25476 ；https://blog.axiaoxin.com/post/wechat-pay-service-verify/ ；https://blog.csdn.net/qq_23934063/article/details/115184193
- 补充参照：官方**测试号**扫码即得且带客服接口额度（发送客服消息 5 万次/日，见官方接口限制页 https://developers.weixin.qq.com/doc/subscription/guide/dev/api/limit ），适合先验证异步链路，但其定位是开发测试，不应当作长期生产账号。

**风险与成本**：官方通道零封号风险，维护成本低；但对本使用者「文字+图片、1 分钟内回复、可主动推送」三项需求，个人订阅号只能满足「图片可收发、快问快答」，后两项不合格。订阅号消息还折叠在「订阅号」文件夹里，不是聊天列表里的好友式会话。

### 2. 企业微信路线

**没有营业执照的个人能不能注册并建自建应用？能（未认证状态）。**
- 【官方】企业微信帮助中心注册页明说：小团队或个人可在移动端/官网注册页点「**Build a team individually（个人组建团队）**」创建；企业微信免费，可选的企业验证费 300 元起。一个微信号可创建 5 个企业。来源：https://open.work.weixin.qq.com/help2/pc/15422
- 【项目】CowAgent 企微文档：「注册一个企业微信（**个人也可注册，但无法认证**）」，并给出未认证企业的完整建应用流程；多个社区教程实测「消息接口无需认证即可使用」「个人实验可先使用未认证企业当前开放的能力」——注意**不要填虚假企业资料**，以管理后台当日显示为准。来源：https://docs.cowagent.ai/zh/channels/wecom ；https://github.com/RoronoaHaruka/wecom-companion-guide
- 【官方】未认证企业的量化限制（对 1 人自用基本无感）：通讯录成员上限 100、通讯录上限 1000【帮助中心】；内部群（含全员群）上限 500 人；**外部联系人/客户全企业共享上限 100 人**、外部群总量受限。来源：https://open.work.weixin.qq.com/help2/pc/14936 ；https://open.work.weixin.qq.com/help2/pc/20172?person_id=0

**收发机制。【官方】**
- 收：自建应用开启「接收消息」→ 填回调 URL / Token / EncodingAESKey；保存时企业微信发 GET 验证，须 **1 秒内**返回解密后的明文 echostr。之后成员在应用里发的消息以**加密 XML POST** 推送过来；**5 秒不响应断开、重试 3 次**；可直接回 HTTP 200 空串，之后用主动接口异步回复。来源：https://developer.work.weixin.qq.com/document/path/90238
- 发：`POST https://qyapi.weixin.qq.com/cgi-bin/message/send`（发送应用消息），支持文本/图片/语音/视频/文件/图文/markdown/模板卡片等；**没有 48 小时窗口**，频控为：每应用对同一成员 ≤30 次/分钟、1000 次/小时，超量丢弃；每应用每天 ≤ 账号上限数×200 人次。来源：https://developer.work.weixin.qq.com/document/path/96458
- 前置：新自建应用必须把调用方 IP 配进**「企业可信 IP」**，否则接口报 60020 无法调用【官方安全升级公告】：https://work.weixin.qq.com/nl/act/p/32d807ad4c554975 。回调 URL 方面，未认证企业可用 `http://公网IP:端口` 直连（CowAgent 文档）；**认证企业则要求与主体一致的备案域名**【项目文档】。
- 另有 2025–2026 新形态「企微智能机器人」：支持单聊/群聊 @、流式回复和长连接接入（CowAgent、LangBot、AstrBot 均已支持），可作自建应用之外的备选；本次未深挖其微信插件侧体验。

**成员能在个人微信里收发吗？「微信插件」2025–2026 仍然存在。【官方+项目】**
- 机制：管理后台「我的企业 → 微信插件」生成邀请二维码（有效期 7 天），成员用**个人微信扫码关注**后，即可在微信「通讯录 → 我的企业」入口里接收该企业的**应用消息和会话消息**并回复。
- 企业微信开发者中心 FAQ 至今仍在维护微信插件排障条目（检查「接收应用消息」开关、应用是否被停用等），CowAgent 2026-10 更新的文档仍以此作为「让外部个人微信用户使用」的标准步骤。来源：https://developer.work.weixin.qq.com/document/path/90315 ；https://docs.cowagent.ai/zh/channels/wecom
- 注意事项（拼凑自帮助类页面与官方发送文档）：不能勾选「仅在企业微信中接收消息」「成员使用微信插件时需要使用企业微信客户端」；应用不能停用；全员群超 2000 人不同步到插件。若在管理端给应用设了「在微工作台中始终进入主页」，则**微信端只能收到文本且截断为 20 字节**，其他类型会被转成「去企业微信查看」提示【官方发送文档注记，见 path/96458】——配应用时避开这个开关。
- 体验定性：会话出现在微信里、能收能回、推送即时，但身份是「某企业的某应用」，不是个人好友；首次需装企业微信 App 完成注册/成员侧设置。

**风险与成本**：全官方 API，正常自用无封号概念；主要成本是常驻一台固定公网 IP 服务器和后台配置（CorpID/AgentId/Secret/Token/AESKey/可信 IP）。这是**唯一同时满足「1 分钟内异步回复 + 无窗口真主动推送 + 个人可注册」的老牌官方路线**。

### 3. 微信客服路线（kf）

**开通门槛。【官方条款】**
- 《微信客服功能服务条款》2.2：使用前**必须先注册一个企业微信号**，再经企业微信在 kf 页面开通；**企业微信未完成企业验证且未绑定视频号时，可咨询的微信用户数量有上限**（达上限后不能接新用户，老用户可继续；具体数值条款只说「以实际展示页面为准」，本次未查到官方公开数字）。完成企业验证并绑定视频号后不限量。来源：https://kf.weixin.qq.com/kf/eula
- 入口形态【官网】：可在微信内视频号、公众号、小程序、微信搜索、微信支付凭证及微信外 App/网页接入；官网登录方式就是「使用企业微信扫码登录」。来源：https://kf.weixin.qq.com/
- **来源冲突，须实测**：CowAgent 的微信客服通道把准备条件写为「**注册并已认证的企业微信** + 已开通微信客服能力」。与条款「未验证可开通（限量）」不完全一致——可能 API 接管模式要求更高，或项目文档取保守口径。对「只有自己一个人咨询」的场景，即便限量版大概率也够用，但**能否以未认证主体开启 API 收发，建议注册后在后台当日实测，不要预设**。来源：https://docs.cowagent.ai/zh/channels/wechat-kf

**用户侧体验**：在微信里点客服链接（形如 `https://work.weixin.qq.com/kfid/kfc…`）或扫二维码，或从公众号/小程序/视频号的「联系客服」进入一个**客服会话窗口**，外观接近普通聊天，可发文本/图片/语音/视频/文件。对自用者来说就是「多一个置顶客服会话跟 AI 聊天」，不需要加好友、不需要关注公众号。

**API 收发机制（与自建应用不同，容易踩坑）。【官方】**
- 收：回调只推一个 `kf_msg_or_event` **事件通知**（含 10 分钟有效的 token 和 open_kfid），**消息正文不在回调里**，必须再调 `POST https://qyapi.weixin.qq.com/cgi-bin/kf/sync_msg` 用游标增量拉取（仅近 **3 天**消息；游标须入库保存）。来源：https://developer.work.weixin.qq.com/document/path/94670
- 发：`POST https://qyapi.weixin.qq.com/cgi-bin/kf/send_msg`，调用应用须先被配置到「微信客服-可调用接口的应用」。硬限制：**仅当客户处于「新接入待处理」或「由智能助手接待」状态可发；客户发消息后 48 小时内最多发 5 条**，客户再发才刷新额度。来源：https://developer.work.weixin.qq.com/document/path/94677
- 条款 2.4 亦明说：48 小时后**无法通过客服账号主动向微信用户发送信息**。
- 结论：kf 的异步回复在 48 小时窗口内完全成立（AI 慢至几分钟没问题），但**定时提醒/长期主动推送不成立**——这是它与企微自建应用的本质区别。

### 4. 个人微信号机器人框架现状（2025–2026）

#### 4.0 先说格局变化：2026 年官方 ClawBot 把这一节的答案改写了

- 【官方仓库】`Tencent/openclaw-weixin`（2026-03-27 建仓）：OpenClaw 的微信渠道插件，`npx -y @tencent-weixin/openclaw-weixin-cli install` 安装，扫码登录，特性为「Text, image, voice, file, and video messages」「Long-poll message delivery and typing indicators」，要求 OpenClaw ≥2026.3.22、Node ≥22.13。来源：https://github.com/Tencent/openclaw-weixin
- 【官方协议文档】其 iLink 协议为纯 HTTP/JSON：`POST /ilink/bot/getupdates` **长轮询收消息（服务端 hold 约 35 秒，游标 `get_updates_buf`）**，`POST /ilink/bot/sendmessage` 发消息，域名 `ilinkai.weixin.qq.com`。**不需要公网回调、不需要常驻 Windows、不碰个人号登录态**——你聊天的对象是微信里新增的一个 ClawBot 机器人会话，不是「你的号被程序接管」。来源：https://github.com/Tencent/openclaw-weixin/blob/24de5c9eb0dd5e595d7e2d090ed8a3f82870d42c/docs/protocol_zh_CN.md
- 【官方文档站】OpenClaw 渠道列表注：微信「通过二维码登录使用腾讯 iLink 机器人；**仅支持私聊**」。来源：https://docs.openclaw.ai/zh-CN/channels
- 【项目】AstrBot 文档：其「个人微信」适配器（v4.22 引入）即基于腾讯官方 `openclaw-weixin`，扫码+长轮询、无需 Webhook；手机端要求 iOS≥8.0.70 / Android≥8.0.69 且微信含 ClawBot 插件；图片/视频/文件可收发，语音由微信云端转文字。来源：https://docs.astrbot.app/platform/weixin_oc.html
- 【社区】主动推送的真实边界（官方文档未承诺，均为社区拆解/实测，口径有出入）：`sendmessage` 必须回带入站消息的 `context_token`，绑定后**第一句话必须由用户先发**；PushPlus 的 ClawBot 渠道说明称「每下发 10 次消息后需要主动发起一次对话、每隔 24 小时也需要一次主动对话」；亦有社区实现称文本用空 context_token 可长期推送、媒体必须带 token、被拒（ret:-2）后需用户发消息激活。稳妥结论：**日常你来我往没问题；把 ClawBot 当无限冷启动推送通道不可靠，重要提醒请配企微应用消息兜底。** 来源：https://www.pushplus.plus/doc/channel/clawbot.html ；https://github.com/Jia-HuaWu/dsh-wechat-clawbot
- 【社区】其他限制：2026-03 上线初期为灰度（iOS 优先）；电脑端微信一度看不到 ClawBot 会话入口；网关停机数小时后 token 失效需重新扫码（errcode -14 会话过期，CowAgent 文档称其客户端会自动清凭证重新拉起扫码）。

### 6. 中转层：Cloudflare Worker 做回调 + 队列异步链路

**结论：入站回调放 Worker 完全可行且有成熟做法；整条异步链路成立与否，取决于「回推通道」而不是队列本身；且回推（出站调微信 API）这一步不能放在 Worker 上，要落回固定 IP 的云服务器。**

**① Worker 做回调地址：可行。【官方约束 + 社区实现】**
- 微信侧只要求回调 URL 是 http/https 的 **80/443**、能做签名校验、能收发 **XML**（公众号）/加密 XML（企微）——Worker 的 HTTPS 公开 URL 天然满足 443 要求。公众号验签 = `sha1(sort(token,timestamp,nonce))` 比对 signature 后返回 echostr；企微验签/解密 = msg_signature + AES（EncodingAESKey），JS 里用 WebCrypto 可实现，社区已有把企微回调完整跑在 Worker 上的代码示例与 2025 年《Cloudflare 构建公众号后端（含 AI 聊天）》教程。来源：https://developers.weixin.qq.com/doc/subscription/guide/dev/push/ ；https://www.xugj520.cn/en/archives/cloudflare-serverless-wechat-backend.html
- **域名坑**：优先绑**自己的域名**到 Worker，不要用 `*.workers.dev`。Cloudflare 官方文档明说 workers.dev 域名强制 Browser Integrity Check 且**无法关闭**，某些自动化客户端 UA 会在 Worker 运行前被 1010 拦截；且 workers.dev 在中国大陆的连通性历来不稳定——微信服务器能否稳定回调到 workers.dev 未获任何官方保证。【官方】来源：https://developers.cloudflare.com/workers/configuration/routing/workers-dev/
- 公众号服务器配置对域名**无备案要求**（官方文档只要求 80/443）；企微侧的备案域名要求出现在「可信域名/认证企业」场景，未认证用 IP:端口回调可绕开（见 2 节）。

**② 5 秒问题：用队列把「接收」与「生成」解耦，是正解。**
- Worker 收到 POST 后只做：验签/解密 → 以 **MsgId 去重**（官方明确推荐，3 次重试会重复投递）→ 写入 **Cloudflare Queue（首选，至少一次投递）/ D1 / KV** → 立即返回 `success`（公众号）或 HTTP 200 空串（企微）。这一步是毫秒级，稳稳落在 5 秒内；**绝不要在回调里同步等大模型**。
- AI 侧消费有两种：(a) AI 服务器**轮询** Worker 暴露的拉取接口/D1（出站主动连接，无入站白名单问题）；(b) Queue 的 consumer Worker 直接 fetch AI 服务器的 Webhook。两者都成立。

**③ 回推环节的限制，才是链路的真正瓶颈：**
- **公众号个人订阅号：链路断在这里。** 没有客服消息接口，队列里攒好的答案没有任何 API 能推给用户，只能等用户再发消息时被动带出。队列解决不了权限问题。
- **公众号认证服务号 / 微信客服：48 小时窗口 + 条数上限**（客服消息 5 条/48h；kf 同）随通道走，队列只能保证「窗口内必达」，救不了过期窗口。
- **企微自建应用：链路完整成立**，`message/send` 无窗口，是异步架构的最佳搭档。
- **ClawBot：根本不需要 Worker**——iLink 是出站长轮询，AI 服务器自己拉消息自己回，天然异步；Worker/队列在这条路线里没有位置。

**④ 出站调微信 API 的 IP 白名单问题（最易忽略的一坑）。**
- 【官方】公众号：只有白名单内 IP 才能调获取 access_token 的接口（错误 61004/40164），access_token 2 小时有效、需中控式缓存。来源：https://developers.weixin.qq.com/doc/subscription/guide/dev/api/
- 【官方】企微：新自建应用**只有「企业可信 IP」内的 IP 能调任何接口**（60020）。来源：https://work.weixin.qq.com/nl/act/p/32d807ad4c554975
- Cloudflare Workers 的**出站 IP 不固定**（共享边缘出口、会变化；社区的 Worker 示例甚至专门做了一个 `/myip` 端点让用户「多次调用观察 IP 是否变化」再填白名单——这本身就说明不可靠）。因此：**access_token 的获取与所有回推 API 调用，应由使用者已有的固定 IP 云服务器执行**；Worker 只做入站边缘（验签、解密、入队），服务器轮询队列取消息、生成回复、再以白名单 IP 直调微信 API。按这个分工，整条链路每一环都在官方规则内成立。
- 附带细节：图片回复在公众号/企微/kf 里都不是「直接发图片 URL」，而要先调素材上传接口换 MediaId（临时素材），这一步同样走服务器出站；ClawBot 则有自己的 CDN 上传接口（getuploadurl），由网关完成。

## Could not verify / 存疑点

1. **「个人服务号」的接口权限**：开放注册（2024-10）与「权限等同个人订阅号」均来自壹伴等二手来源与博客，未找到微信官方文档单列说明；结论可信度高（多源一致且与「客服消息仅企业认证」的官方规则自洽），但建议使用者注册后在后台「接口权限」页实测确认。
2. **未认证企业微信能否开启微信客服 API 接管**：kf 官方条款说未验证可开通（限咨询人数），CowAgent 文档要求已认证企业微信，两者口径不一致；且咨询人数上限的具体数字官方未公开（条款称以页面展示为准）。
3. **ClawBot 主动推送的精确规则**（24h？10 条？文本是否可空 token 冷发？）：官方协议文档只规定 sendmessage 需带 context_token，量化窗口均为社区拆解且互相有出入；按「不可靠」规划即可，不要按任一社区数字做 SLA。
4. **PadLocal 与 Gewe 付费版的现行价格**：PadLocal 社区口径 200 元/月 vs ~50 元/月冲突、官网未公示；Gewe 定价页只有计费模式无单价。二者下单前须以各自控制台实时价格为准。
5. **WeChatFerry 归档的精确日期**：仓库现状为 Public archive（2026-11-07 打开确认），搜索索引显示归档于 2026-07-10；作者「停止维护」的最早公开信号是 2025-06 的 V2EX 帖。两个时间点含义不同（宣布停维 vs 仓库归档），报告中已分别表述。
6. 未实测任何路线（本任务为案头调研）：企微未认证自建应用 + 微信插件的完整链路有多方社区教程背书，但微信后台策略调整频繁，正式投入前建议按 CowAgent 企微文档半天内跑一次端到端验证。
